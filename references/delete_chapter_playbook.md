# 删除章节 / 附录 + 悬空引用清理 SOP（跨品种通用）

适用：用户要求「删去某个章节 / 附录 XX」。配套的 `scripts/delete_chapter.py` 是配置驱动的
通用执行器；本文件记录配方与踩坑。品种专属的章节名、文件编号、数值只在 `references/`
下的示例 JSON 里出现，**禁止写进脚本默认值**。

关联：`chapter_refactor_playbook.md` §3（定位 10 条硬约束）、§4（写入硬约束）、
§3.6（跨 run token）；`revision_playbook.md`（沿革表只追加、历史不就地改写）。
删除是比重构更激进的动作——**引用清理稍有遗漏就会留下悬空指针或误删相邻章节**，务必按本 SOP。

---

## 1. 一句话原则

删除一个章节 = **删掉它本身** + **清掉全书所有指向它的引用** + **保留结尾锚点与他人条目**，
三者缺一不可；且「清引用」必须**段落 + 表格单元格全扫描**。

---

## 2. 执行流程（六步）

1. **只读定位**：先扫描目标章节标题出现次数与位置，区分「目录(TOC)伪条目」与「真正文」。
   - 真实章节标题取**最后出现**（TOC 在前、正文在后）——同 `chapter_refactor_playbook §3.3`。
   - TOC 条目取**首次出现**，与正文一并删除（本手册目录是**静态手工目录**，不是域，
     不会自动更新，必须手动删条目）。
2. **确定删除边界**：正文范围 = 真实标题 → `tail_anchor`（通常是「—— 本手册完 ——」）之前，
   **标题本身删、结尾锚点保留且全文唯一**。若目标章节后面还有其它附录，须改用「下一章锚点」
   而非结尾锚点，避免把后续章节一起删掉（本脚本当前仅支持 `tail_anchor` 终止型删除；
   中间章节删除请用 `refactor_chapter.py` 或先扩展脚本支持 `next_anchor`）。
3. **全扫描引用**（★最关键）：遍历 body 下**所有段落 p + 所有表格单元格 tc**（`iter w:t`），
   检索目标章节的全部写法：`附录 X`、`附录X`、`X.1`~`X.9`、章节标题全文、内容别名。
   - **血泪教训**：删附录 G 时首轮只扫 `doc.paragraphs`（段落），漏掉两处藏在表格单元格里的引用
     （第 3 章操作卡「各组分浓度见附录 G RP-02」、附录 E 表格行「附录 G 一律填需查」），
     直到验收才用「含表格的全文本扫描」发现残留 2 处，最终整单回退。**第一轮就要扫表格。**
4. **分类改写引用**（不是一律删字）：按引用所在语境分三类处置：
   - **TOC 条目** → 整段删除。
   - **版本沿革表 / 增量说明中的历史记述** → **就地软化措辞**，保留「曾发生」的历史事实，
     只去掉指向被删章节的指针。例：「4 张表迁入新增附录 H「…」」→「4 张表并入本手册源文件汇总
     （原「源文件清单」附录，本版已移除）」。历史记述不整段删（违背沿革表只追加原则）。
   - **正文交叉指针** → 去掉指针、保留有用内容。例：「见附录 H.4（S17～S22）」→「（S17～S22）」。
   - 若引用内容本身完全依赖被删章节、无法等价改写，则连同该句精简，但须在验收里说明。
5. **执行删除 + 改写**：脚本内**先改引用、后删章节块**（删块会移除元素，先删就改不到了）。
6. **验收四件套**（任一不过即抛错、不保存）：
   - **残留零命中**：`verify_absent` 每个关键词在全文本（段落+表格）出现 0 次；
   - **保留锚点**：相邻章节/附录（`verify_present`）仍在；
   - **结尾唯一**：`tail_anchor` 全文恰好 1 次；
   - **块级 diff 零误伤**：与备份比对，差异应只有「TOC 删除 + 目标章节整块删除 + 少量引用改写」，
     其余块逐字不变（用 difflib.SequenceMatcher 打印 opcodes 人工核对）。

## 3. 硬约束与踩坑

| # | 约束 | 后果 / 教训 |
|---|---|---|
| 1 | 真实章节标题取最后出现，TOC 取首次出现 | 取错会把内容插进目录区或删错（§3.3） |
| 2 | **段落 + 表格单元格全扫描** | 只扫段落 → 漏表格引用 → 悬空指针（删 G 回退） |
| 3 | 引用改写用 run 级精确替换 | 跨 run 的 token 若静默跳过会留残留；脚本遇跨 run **报硬错**，改用整段回写 |
| 4 | 历史记述就地软化、不整段删 | 保住沿革表「只追加、历史不改」的契约 |
| 5 | 结尾锚点保留且唯一 | 误删结尾标记会破坏尾部结构完整性 |
| 6 | 删除边界不得越过下一章节 | 删中间章节时用 next_anchor，别用 tail_anchor |
| 7 | 先备份、输出不覆盖输入 | 删错可回退；脚本强制 `output != input` |
| 8 | 用 `expected_hits` 锁定每条改写命中数 | 命中数不符即报错，防止改多/改漏 |

## 4. 配置 schema（`delete_chapter.py --config`）

```json
{
  "chapter_anchor": "5  附录 X  章节标题全文",
  "tail_anchor": "本手册完",
  "delete_toc_entry": true,
  "ref_rewrites": [
    {"scope": "cell", "locate": "所在行的锚文本", "find": "旧引用",
     "replace": "新表述", "expected_hits": 1},
    {"scope": "para", "find": "见附录 X.4（...）", "replace": "（...）", "expected_hits": 1}
  ],
  "verify_absent": ["附录 X", "附录X", "X.4", "章节标题全文"],
  "verify_present": ["相邻附录标题", "本手册完"]
}
```
- `scope`：`para` / `cell` / `any`（默认 any）。`locate` 可选，把改写限定到含该锚文本的块。
- `expected_hits`：该规则应命中的块数，不符即抛错。
- 运行：`python delete_chapter.py --input SRC --output OUT --config CFG [--dry-run]`
- `--dry-run` 只打印删除范围与引用命中预览，不写盘；`--selftest` 内置自检。

## 5. 算例（红霉素 v7 删附录 H）

见 `delete_chapter_example_lk080_h.json`。真实执行结果：
- 删除 TOC 条目 1 个 + 正文 16 个元素（H 标题 + H.1~H.5 + 5 张表）；
- 改写引用 3 处：版本沿革表 v7 行（软化）、附录 G·G.3 表格 S16 行（去指针）、
  附录 G·G.3 说明段（去指针）；
- 验收：`附录 H / 附录H / H.1~H.5 / 源文件清单与效力总览` 残留全 0，
  附录 A~G 与结尾标记完好，块级 diff 仅上述三类差异。

> 注意：当时误判 [253]/[254] 属于附录 G，实际它们在附录 H.3 内部随 H 一并删除，
> 不构成 G 的悬空引用；真正需要就地改写的外部引用只有版本沿革表 v7 行 1 处。
> 这提示：**先确认引用所在块的归属，再决定改写还是随删。**
