# 手册结构与药品 QC 内容口径（易错点汇总）

把"QC 文件梳理 → 检验手册"做成可复用的结构，并记下药品检验里容易写错的内容口径。

## 1. 手册总体结构（聚多卡醇注射液范例，21~29 页）
```
0  编制说明 / 溯源声明（注明"以现行生效 STP/SOP 为准"）
1  产品基本信息（规格、贮藏、适应症、执行标准）
2  一页速览总览表（全部检验项，如 14 项，含方法/限度/关键物料速查）
3  逐项操作卡（每检验项一张：操作步骤 / 系统适用性 / 计算公式 / 结果与判定 + 🔴关键点框）
4  验证结论摘要（横向 9 列表，必要时 landscape section）
5  附录 A~G
     A 官方限度依据逐项对照表
     B~D 沿革/收严记录/需人工核对项
     E 需人工核对清单（识别存疑项）
     F 可选扩展（按需补充）
     G 检验物料清单（备料核对清单）★本技能重点
6  参考文献与溯源说明（含"尚未读取"红字警示）
```

## 2. 多阶段演进路径
- **v1（速览版）**：总览表 + 操作卡，不含 SOP 原文。
- **v2（SOP 嵌入版）**：卡内挂浅底 SOP 引用块（标注章节号+页码），数值冲突**以现行 SOP 就地更正**，旧值保留在对照列/编者注供审计。
- **附录 G（物料清单）**：按六类物料分节 + 检验项×物料矩阵；用途=备料核对，非成本台账。

## 3. ⭐ 数值冲突 / 收严限度（必须以现行 SOP 02 为准）
| 项目 | 验证报告时期（旧） | 现行 SOP 02（已更正） |
|---|---|---|
| 残留溶剂—乙醇 | 37.0～42.0 mg/ml | **37.5～41.5 mg/ml** |
| 有关物质 LK036-C 与主峰分离度 | ≥1.0 | **≥1.2** |

- 质量标准 P6 密度换算注推得 **37.4**，与该标准自身下限 37.5 自相矛盾 → 判为标准内部笔误，
  以正文 **37.5** 为准（写入附录 D 第 1 条 + 附录 E 第 5 条）。
- 三者易混点务必在卡内写明：
  - 校准因子按 **1.0**（1.2 仅为验证实测响应因子，日常主成分自身对照法按 1.0）
  - 有关物质分离度 **1.2**
  - 含量测定分离度 **1.5**

## 4. 项目范围口径
- **渗透压摩尔浓度并非聚多卡醇注射液检验项目** → 删除，改为 14 项（补入鉴别）。
- 凡 SOP 未载的对照品证书信息（批号/效期/保存）填"需查"；**方法学验证报告批号（如 WRS…）
  属验证用信息，不得当作对照品证书信息补入**——来源不同，不可互相替代。
  但**批检验记录扫描件**属实际执行记录，可逐份汇总回填批号 / 供应商（标注来源、留「待核对」）；
  分级口径见 `references/revision_playbook.md` §4。

## 5. 文档级要点
- 默认模板是 Letter + 16.5cm 版心 → 必须显式设 A4 + 2.0cm 边距（见 python_docx_pitfalls.md）。
- 宽表（>25.7cm）放进 landscape section，末尾 restore_portrait，保持 section 数量一致。
- 预览面板会独占锁目标 docx → 用 OUT_OVERRIDE 构建到临时路径再回写（见避坑第 9 条）。
- **单格红框（关键点框）必须加 `w:cantSplit`**，且要插在 `w:trPr` **首位**（否则 Word 忽略）——
  否则框体内容变长后会在页边界断成两半，框标题留在上一页、内容在下一页。
- 富文本：需要 `**加粗**` 标记时不能直接 `add_run`（标记会原样显示）；
  写一个 `add_rich_runs(p, text, base_bold=False)` 按 `**` 奇偶段切分加粗，`\n` 转软换行。

## 6. 把真实偏差/OOS 案例挂进「关键点/易错点」
手册的价值在于**让人在操作现场看到别人踩过的坑**。把历史偏差处理报告 / OOS-OOT 调查报告
提炼后挂进卡内红框，是最有效的形式。

**推荐做法（保持结构不破）**：
1. 案例内容外置成数据文件（如 `deviation_cases.py`），字段：
   `code / kind / found / item / grade / phenomenon / root_cause / impact / decision / capa / keypoint / key_flag`
   再加 3 个**精简字段**（`phenomenon_s` / `root_cause_s` / `decision_s`）专供窄栏汇总表使用——
   完整叙述太长，塞进表格会挤爆版面。
2. `card()` 加 `case_code` 参数，把 `key_flag + keypoint` 追加到既有 key_text 末尾：
   **红框数量保持不变**（否则读者会以为是新的检验项）。
3. 卡内条目写法：`<编号> △ 真实<类型> <报告编号>（<日期>）：<现象一句话>。<根因>。<可操作的规避要点>`
   （成品文档内一律 ★ / ● / △；🔴 / ⚠️ 在宋体下不稳，见 `revision_playbook.md` §3）
   —— 最后一段必须是**读者下次能照做的动作**，不是复述调查过程。
4. 附录 B 扩写为「通用处理指引 + B.2 历史案例复盘（汇总表 + 逐案叙述）+ B.3 共性规律」。
5. 附录 E 补人工复核提示：签批 PDF 与电子版 DOCX 的批号/勾选/签署差异、手写判读存疑处。

**脱敏**：偏差/OOS 报告含员工真实姓名。手册内部传阅时用**岗位描述**替代
（QC 主管 / 检测人员 / 新入职人员 / 取样人员 / 分析部经理），保留编号、日期、批号、限度等可追溯信息。
例外：SOP/质量标准**封面审批栏**的签署人属于文档签署链，是文档溯源信息，可保留。

**共性归纳是这一节的灵魂**：4 起案例的共性往往是
「根源类别都是人员/行为」「异常都呈整齐的系统性偏差 → 指向操作而非仪器」
「复测都证明产品无问题」「CAPA 都是重新配制 + 人员再培训」。
把共性单列一节，比逐案罗列更能让读者记住。

## 7. 验收清单（文本级 / OOXML 结构级 / 视觉级 三层）

**文本级**（每次生成或修订后必查）
- 被删小节在全文 **0 残留**（注意 U+FFFC 伪影，见避坑第 8 条）；SOP verbatim 片段在目标表内 0 次。
- 物料编号全部出现在对应表首列；关键数值（0.1μm/0.45μm/25ml/4.0g/3.39g/0.84g/2.5cm/21G/1000lx 等）命中。
- 旧版本串 / 旧汇总数字 0 命中，新增编号与限度全命中；`**` 残留 0（段落 + 所有表格单元格一起扫）。
- 案例类内容额外核对：红框数量不变；每个案例编号 ≥1 次；案例相关人名 0 残留；被删小节与已去列未回流。

**OOXML 结构级**（成稿修订零回归的主力；PDF 导不出时尤其重要）
- 与 baseline **逐格内容比对**，除白名单单元格外零改动。
- `tblW` / `tblGrid/gridCol` / 每行每格 `tcW` 三者一致且 `tblLayout=fixed`；列宽合计恰等于所在 section 版心
  （纵向 17.00cm，横向 14570tw = 25.70cm）。
- `sectPr` 数量与内容一字未动；总表数、总段落数、关键表维度（如矩阵 18×6）按期望值联动。
- `tblHeader` / `cantSplit` 保留；`w:br[type=page]` = 0；`w:pBdr` 分隔段计数 = 卡数 − 1。
- `rFonts` 四属性（ascii/hAnsi/cs + eastAsia）与 `w:sz` / `w:szCs` 成对齐全。
- 误报规避：「裸代号 0 命中」只扫矩阵**数据格/数据行**（全文扫会命中物料表编号列）；
  顿号计数排除列头；关键点框计数用精确串 `● 关键点 / 易错点` 防目录假阳性。

**视觉级**（需 PDF）
- 逐页 ViewImage 确认无溢出/截断/乱码/豆腐块，横向页右边界在页内；红框不跨页撕裂、无孤立红框页。
- `orphan_kc` 双判据：每页红框数 ≤ 该页卡标题数，且逐卡配对「第 k 个红框页 == 第 k 个卡标题页」。
- **本机 Word COM 被沙箱拦截时，视觉级整层标 SKIP**，并明确告知用户「PDF 需手动导出、逐页目视待补」；
  不得把结构级通过表述为版式已验收。修订态完整断言集见 `references/revision_playbook.md` §8。

## 8. 已代码化的可复用组件（本技能内）
以下模式已从"工程脚本"沉淀为 skill 内可直接调用的代码，做新品种手册时直接 import 复用：

- **红框多序号逐条分行**：`docx_table_toolkit.add_key_callout(doc, text)` 内部用
  `_split_numbered()` 按带圈数字 ①②③… 把文本切成多条独立成段；无序号卡片保持单段，行为不变。
  挂了偏差案例（末尾带 ⑥ △…）会自动在该序号处断开，读起来一目了然。
- **页眉描述文字 + 页脚页码域**：`docx_table_toolkit.add_header_footer(doc, header_text)`
  统一注入页眉描述文字与「第 X 页 / 共 Y 页」（PAGE/NUMPAGES 域），多节文档自动链接沿用。
- **偏差案例挂接**：`deviation_cases_template.py` 提供 `DEVIATION_CASES` 数据结构 +
  `attach_case(key_text, case_code)`，把某案例关键点追加到卡内 key_text，再传给
  `add_key_callout`，**红框数量不变**。
- **物料清单 + 矩阵**：`materials_template.py` 的 `MATERIALS` + `build_matrix()` 自动派生
  「检验项 × 物料」矩阵，杜绝手工维护两份不同步。
- **导出 PDF（按环境分支）**：`scripts/export_pdf.ps1` 用 Word COM 导出，已内置 `Fields.Update()`；
  本机 COM 被沙箱拦截时须由用户在 Word 手动导出，脚本保留待环境修复（见 python_docx_pitfalls.md §10 / §12）。
- **成稿修订与升版**：`scripts/patch_existing_manual.py`（列宽 / 字体）、
  `scripts/verify_revision.py`（三层零回归断言）、`references/revision_playbook.md`（完整 SOP）。

> 注：第 6 节描述的「card() 加 case_code 参数」是最早的草图；落地实现改为
> `attach_case()` 独立函数 + `add_key_callout()` 通用渲染，解耦更干净，新品种手册照此调用即可。
